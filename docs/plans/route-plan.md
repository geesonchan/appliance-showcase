# 丁：本站文件不经过本机网络连接 · 计划（断连这一项的最后一个实验）

> Leo 2026-11-07 下午：「断连这一项的最后一个实验：丁。只在循环脚本里加选项，不改测试、不改拍照脚本（这一步我现在就批了）」。
> 背景：`docs/plans/server-reset-plan.md` 第 2 节的丁；甲、乙、热身三组在 `norton-experiment-plan.md`、`warmup-plan.md`。

## 1. 为什么试丁

三组共 1,800 次新浏览器打开，出事 15 次：

| 组 | 条件 | 出事 |
|---|---|---|
| 甲 | 照现在 | 9 次，1.5% |
| 乙 | 智能防火墙关 | 3 次，0.5% |
| 热身 | 先打开一个小文件 | 3 次，0.5% |

每次都一样：本机上的新连接晚到约 10 秒，或者已经连上的连接回应晚约 10 秒才送完；另一个进程的心跳也同时卡住。

丁让浏览器要本站文件时，根本不走本机的网络连接。这一组要回答的是：

- 毛病出在"本机网络连接"这一段，那么丁绕得开；
- 毛病是整个程序（或整台电脑）一时被冻住，那么丁也绕不开。

## 2. 丁怎么做

- 新选项 `ROUTE=1`，只加在 `scripts/serverResetLoop.mjs`。
- 每次打开，要测的那个浏览器上下文挂一个 `context.route`：
  - 凡是本站地址（`http://localhost:4176/…`）的请求，都由 Playwright 从 `dist/` 读出文件直接回答；
  - 页面本身（`/?quality=high&qualityLock=1`）回答 `index.html`；
  - 文件类型照扩展名给：`.html`、`.js`、`.css`、`.woff2`、`.txt` 等；
  - 找不到的文件回 404，并记进这一次的记录（`routeMisses`）。正常应该是 0。
- **地址不变**，浏览器看到的还是 `http://localhost:4176/…`。
- Playwright 和浏览器之间用的是管道（pipe），不是本机网络连接。所以开了丁以后，页面和它的文件都不经过本机网络连接。
- **不压缩**：文件原样送，传输的字节比服务器送的大，但不影响"卡不卡"。
- **其余照旧**：`MODE=fresh`，600 次，每次新浏览器，桌面和手机轮流，等画布出来再等 2.5 秒；同一份 `dist/`（`index-DXl3ZdsD.js`）。
- **心跳和 typeperf 照样记**：
  - 服务器照样开着，心跳仍然每 250 毫秒打本机服务器，作为对照；
  - 心跳卡、页面不卡，就说明丁绕开了。
- **核对丁真的绕开了**：服务器记录里应该只有心跳的请求（`/`）。如果服务器收到任何页面或本站文件的请求，就是没接好，这一组作废，照实报。
- 命令：`MODE=fresh ROUTE=1 COUNT=600 node scripts/serverResetLoop.mjs dist <输出文件夹>`
- 防火墙开着跑。跑前读一次状态，跑的时候每 5 分钟读一次，跑完读一次，都是只读。状态有变就记下时间，分开计算。
- 跑前读电源设置，跑后查系统日志。中间有睡眠或待机，这一组作废。

## 3. 怎么判断（Leo 定的）

- **丁的页面 0 次卡住、0 次断连、0 次画不出来 → 丁就是修法。**
  - 再另写计划，把它接进测试和拍照脚本。
- **丁照样卡 → 说明是整个程序被冻住，测试环境绕不开。** 这一项按**戊**结案：
  - 红了照实报、重跑；
  - 记下每次的时间。
- **不管哪种结果，这一项到此为止，不再加实验。**

**参考：0 次有多大把握**（丁如果完全没用，600 次一次都不出的可能）：

- 按甲组的 1.5%：(1 − 0.015)^600 ≈ 0.0001，约万分之一；
- 按三组合计的 15/1,800 ≈ 0.83%：约 0.7%；
- 按乙组、热身组的 0.5%：(1 − 0.005)^600 ≈ 4.9%，约二十分之一。

所以就算是 0 次，也有约 5% 的可能只是运气。这一点照实写在报告里，判断仍照上面 Leo 定的。

## 4. 已知的漏洞

- 丁不走真正的 HTTP：响应头、缓存、压缩都不经过。接进测试以后，测试测不到这些。
- 每个测试的浏览器上下文都要接上，探针和拍照脚本也要接。漏接一个，它测的就是另一条路。
- 接错了，可能出一个只在测试里有、看起来却像网页毛病的问题。
- 丁管不到 Playwright 自己的管道，也管不到浏览器内部。如果卡的是这些，丁照样卡。

## 5. 这一步只改什么

- 只改 `scripts/serverResetLoop.mjs` 和 `scripts/resetLoopStats.mjs`，加它们的测试。测试先在旧代码上变红，再写实现，单元测试全过。
- 不改测试、不改拍照脚本；不碰 Norton 的任何设置；不碰网页代码。

## 6. 丁的结果（2026-11-07 15:29:16–16:16:34，exit 0）

- 防火墙：跑前 15:29:14、跑的时候 9 次、跑完 16:16:47，都是"开"（`266240 / 0x041000`）。状态没变过，所以没有分开计算的。
- **页面：600 次，卡住 0，断连 0，画不出来 0。**
- **核对丁真的绕开了**：服务器收到心跳的请求 10,907 个，其他请求 **0** 个；`dist/` 里找不到的文件 0 个；失败的请求 0 个。
- **心跳这个对照**：600 次里一次都没卡，失败 0 下，最慢 287 毫秒。
  - 甲、乙、热身三组的心跳一共失败 31 下，每一下都落在页面出事的那几秒里。
  - 页面不连本机服务器以后，心跳也不卡了。
- **照第 3 节 Leo 定的：丁的页面 0 次 → 丁就是修法。** 再另写计划，把它接进测试和拍照脚本；这一项的实验到此为止。
- **照实写的两点**：
  - 心跳也没卡，所以"心跳卡、页面不卡"这个对照没有出现。这一组说明的是：浏览器不连本机服务器的时候，页面和心跳都不卡；而不是"毛病照样发生、丁把它挡在外面"。
  - 丁如果完全没用，600 次 0 次的可能：按三组合计 0.83% 约 0.7%，按 0.5% 约 4.9%（第 3 节）。按三组合计每 150 分钟 15 次算，47 分钟里心跳一次都不卡的可能约 0.9%。
- 这次跑的时候，Leo 看的本地预览（4173 端口）开着，没有请求；甲、乙、热身三组跑的时候没有它。
