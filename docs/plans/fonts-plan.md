## 1. 现在是怎么加载的

- `index.html` 的 `<head>` 里有三行：两行 `preconnect`，一行 Google 的样式表：
  `fonts.googleapis.com/css2?family=Cormorant+Garamond:wght@300;400;500;600&family=Inter:wght@300;400;500;600&display=swap`
- 这张样式表放在 head 里，排在网站自己的脚本前面。所以样式表没回来（或者没失败）之前，页面一个字都不画，程序也不启动。
- `display=swap` 只管样式表回来之后的字体文件：字体文件没到时先用系统字。
- 用到字体的地方：
  - `src/index.css`：`body` 的字体是 `"Inter", "Noto Sans SC", system-ui, sans-serif`；
  - `tailwind.config.js`：`font-display` 是 `"Cormorant Garamond", "Noto Serif SC", Georgia, serif`，`font-sans` 和 body 一样。
- 实际用到的字重（数过源码，也在浏览器里看过实际加载了哪些）：
  - Inter：400 和 500（`font-medium`，41 处）；
  - Cormorant Garamond：只有 400（标题、套餐名、编号，9 处）。
  - 300 和 600 两档在请求里有，但页面上没有用到。

## 2. 字体文件多大

Google 给这个 Chromium（153）的是**可变字体**：一个文件里包含 300 到 600 全部字重，按字符范围分包。一共 12 个文件（2026-11-06 下载）：

- Inter，7 个文件：
  - latin 48,256
  - latin-ext 85,068
  - cyrillic-ext 25,960
  - cyrillic 18,748
  - greek 18,996
  - greek-ext 11,232
  - vietnamese 10,252
- Cormorant Garamond，5 个文件：
  - latin 37,640
  - latin-ext 33,736
  - cyrillic-ext 23,416
  - cyrillic 21,168
  - vietnamese 11,220
- **12 个合计 345,692 字节（约 338 KB）。**

**页面实际只下载 2 个：Inter latin 和 Cormorant latin，合计 85,896 字节（约 84 KB）。**

- 量的是改前和改后两个版本，三种界面：1440 桌面英文、1440 桌面中文、360 手机中文。每种都只加载了 latin 这一包：Inter 400、Inter 500、Cormorant 400。
- 360 手机上连 Cormorant 都不下载，因为顶栏的标题在 430px 以下是隐藏的。
- 其他 10 个文件只在页面上出现俄文、希腊文、越南文或带特殊符号的拉丁字母（例如 ā、ő）时才会下载。
- 扫过 `data/*.json`、`src/i18n/en.json`、`zh.json` 和源码里所有不是注释的文字：不在 latin 包里的字符只有 ⅛ ⅜ ⅝ ⅞ ≥ → ← ↗ ▾ ▸。
  - 这些字符**不在 Google 的任何一个分包里**，所以现在和改后都是用系统字画的，不会变。

**CSS 会变大。** 原型把 Google 的样式表原样搬进来（48 段 `@font-face`，每个字重、每个分包各一段，只把地址改成网站自己的）。网站的 CSS 从 23,985 字节变成 37,753 字节（+13,768）。

## 3. 授权

- 两款字体都是 **SIL Open Font License 1.1**。
  - 授权原文取自 Google Fonts 的仓库 `google/fonts`：`ofl/inter/OFL.txt` 和 `ofl/cormorantgaramond/OFL.txt`，2026-11-06 下载。
  - 两个文件第一行是各自的版权声明：Inter 是 "Copyright 2020 The Inter Project Authors"，Cormorant 是 "Copyright 2015 the Cormorant Project Authors"。后面的授权正文两份逐字相同。
  - 两个仓库的 `METADATA.pb` 都写着 `license: "OFL"`。
- **允许放在网站自己的文件里。**
  - 授权允许使用、复制、再分发，可以和软件一起分发。条件是每一份副本都要带上版权声明和这份授权，原文是 "provided that each copy contains the above copyright notice and this license"（OFL 1.1 第 2 条）。
  - 授权可以是单独的文本文件。所以计划把两份 `OFL.txt` 和字体放在一起发布。
  - 第 1 条：不能单独卖字体。我们不卖。
  - 第 3 条（保留字体名）：两份版权声明后面都没有写保留字体名，所以 Google 分包后的文件可以继续叫 Inter 和 Cormorant Garamond。
  - 第 5 条：字体本身必须一直用这份授权。用它们显示的网页不受限制。

## 4. 首帧时间：四种网络情况，改前和改后

- 每次都是新开的浏览器、空缓存、1440×900 桌面。改前、改后交替各跑两次（08:57–09:02，在睡眠之前，没有待机）。
- "画布"指 3D 画布出现在页面里并且有了尺寸，从开始导航算起。"字体"指 Inter 和 Cormorant 都加载完。
- Google 的两个地址（`fonts.googleapis.com`、`fonts.gstatic.com`）在浏览器里分别被设成：
  - 拒绝：指到本机一个没有服务的端口；
  - 不回应：指到一个不回包的地址 10.255.255.1；
  - 挂着：指到本机一个只接受连接、一句话也不说的端口。
- 结果（两次的数，用"/"隔开）：
  - **正常**：
    - 改前：画布 0.33 / 0.28 s，字体到 2.10 / 2.12 s（从 Google 来）。
    - 改后：画布 0.16 / 0.16 s，字体到 0.24 / 0.23 s。
  - **Google 直接拒绝**：
    - 改前：画布 0.15 / 0.17 s，但始终没有网页字体，全程系统字。
    - 改后：画布 0.15 / 0.15 s，字体 0.22 / 0.99 s。
  - **Google 不回应**：
    - 改前：画布 **21.17 / 21.18 s**（浏览器 21 秒后放弃连接，`ERR_CONNECTION_TIMED_OUT`），全程系统字。
    - 改后：画布 0.14 / 0.14 s，字体 0.22 / 0.21 s。
  - **Google 一直挂着**，这次量出两种不同的挂法：
    - 连上了但不握手：改前画布 **30.13 / 30.13 s**（浏览器 30 秒后放弃，`ERR_TIMED_OUT`）；改后 0.14 / 0.15 s。
    - 请求发出去以后不回应（HTTP 层挂住，和 11-05 在线上量的"挂着"一样）：改前 **90 秒内一直没有画面**（两次都是，量到 90 秒为止）；改后 0.16 / 0.17 s。
    - 11-05 在线上量的"挂着"等了 120 秒，属于第二种。第一种是这次新发现的：TLS 握手没有回应时，浏览器 30 秒后会放弃。
  - **改后，四种情况下页面都没有发出任何一个去 Google 的请求**：只有两个请求，都是本站的 woff2。
- **另外加量了慢网**（模拟 150 ms 延迟、1.6 Mbps），用来看"字体没到先用系统字"：
  - 改前：画布 2.72 / 2.68 s，字体 4.60 / 4.57 s；
  - 改后：画布 2.70 / 2.69 s，字体 4.51 / 4.55 s。
  - 也就是说，画布出来以后大约有 1.8 秒，文字先用系统字显示，字体到了再换一次。这和现在一样，因为现在已经是 `display=swap`。
- **限制**：这里网站自己的文件来自本机服务器，几乎不花时间。线上是从 github.io 来，首次访问会多下载那两个字体文件（约 84 KB）。因为是 swap，画布不会等它们。

## 5. 画面和文字排版会不会变（锁画质的像素对比）

- **怎么拍的**：`scripts/pixelShots.mjs`，45 个状态，`?qualityLock=1`，高画质。改前、改后各拍两次，交替进行（改前 10:22–10:31，改后 10:31–10:40，改前 10:40–10:49，改后 10:49–10:57）。比较用 `scripts/pixelCompare.mjs`。
  - 10:20 之后系统日志里没有 42、506、507、107、187 号事件，插着电，电源设置是"从不"。
  - 09:03 开始的第一次拍摄作废：电脑 09:08:58 进了睡眠，10:09 前后重启，改前只拍到 31 张。那一组照片另放在一边，没有用。系统日志的原文：42 号 "Sleep Reason: Application API"；187 号的调用者是 `winlogon.exe`；前一秒没有 566 号的输入事件，唯一的 566 号在 187 号之后 1 毫秒，写的是 "Reason WinRT"。
- **3D 画布：45 个状态，改前和改后完全相同（0 像素）**，每个版本自己拍的两次之间也是 0。
- **整屏（含 HTML 文字）：32 个状态完全相同，13 个不同**：
  - 不同的是 `desk-A-materials`、`link-*` 共 10 个、`phone360-zh-A`、`phone390-A`。像素数在 1,598 到 4,610 之间。
  - 每个版本自己拍的两次之间只差 0 到 1 像素，所以这些差别是真的，不是拍摄时机造成的。
  - 差别全在图钉标签里面：每个标签的文字和框的位置都没变（比较脚本记录"0 处文字改动，0 条引线移动"），变的是标签里字的清晰度。
  - **改前的标签发虚，改后更清楚**，见特写 `docs/plans/fonts-plan-labels.png`（`desk-A-materials` 的三个标签放大 5 倍，上面是改前 `index-bnVQuA-J.js`，下面是改后 `index-BxCOFJFQ.js`）。
- **原因已经证明，不是猜的**（D17 的第一种办法：把改变的那一项放回去）：
  - 只拍这 13 个状态，改前版本照旧，但让 Google 的两个地址由本机副本立刻应答，也就是同样的字体文件，只是到得和改后一样早。拍两次（11:00–11:03）。
  - 这样拍出来和改后比：**13 个状态里 12 个是 0 像素，`link-C-noisland` 是 1 像素**。各版本自己两次之间的 0–1 像素波动，在其他状态里也出现过。画布仍然全是 0。
  - 所以差别只来自字体到达的早晚：改前字体大约 2 秒才从 Google 到，正赶上标签出现，标签就画得发虚；改后 0.2 秒就到了。字形本身没有变。
- **排版**：文字的框、引线、面板，在 45 个状态里位置都没有变。
- **线上的客户现在看到的标签**，取决于 Google 那一刻有多快。改后，**字体比标签先到时**标签才是清楚的那一种。这只在本机量过（字体 0.2 秒到）。按第 4 节的慢网数据，改后画布 2.7 秒、字体 4.5 秒，字体在标签之后才到，慢网下标签照样可能发虚。所以证明阶段加拍慢网（见第 8 节），标签发虚本身另登记一条待办，这一轮不修。
- 这是这一轮唯一看得见的变化。

## 6. 中文界面用什么字体，会不会受影响

- **中文字从来不是从 Google 来的。** Inter 和 Cormorant 里没有汉字，Google 的样式表也不提供中文。字体栈里的 `Noto Sans SC`、`Noto Serif SC` 不会被下载，只有设备上已经装了才会用。
- 在这台电脑上量的（Chromium 自己报告每段文字实际用哪个字体画，改前改后各一次）：
  - 1440 桌面中文：Noto Sans SC（本机安装）317 个字形，Noto Serif SC（本机安装，用于标题）8 个，Inter（网页字体，用于数字和拉丁字母）193 个，Consolas 4 个。
  - 360 手机中文：Inter 55 个，Noto Sans SC 55 个，Consolas 4 个。
  - **改前和改后每一项都一样。**
- 客户的设备上，汉字由设备自己的字体画：
  - Windows 没装 Noto 时是微软雅黑；
  - Mac 和 iPhone 是苹方；
  - 安卓一般是系统自带的 Noto Sans CJK。
  - 这一轮不改变这一点。
- **会变的只有在大陆、Google 被挡的设备**：现在那里的数字和英文是系统字，改后会是 Inter 和 Cormorant，也就是设计原本的样子。前提是 github.io 本身能打开（见第 7 节）。
