## 二、查清的几条

每条后面写出处：

- 「文档」是 GoatCounter 官方帮助页 https://www.goatcounter.com/help/visitor-counter（下面简称"帮助页"）。
- 「源码」是 GoatCounter 在 GitHub 上的源码，固定在提交 `c031008`（2026-11-17 的 main）。只在文档没写的地方才看源码，并且写明是从源码看到的，不是文档写的。
- 查的时候只读了文档和源码，没有向任何 `/count` 或 `/counter` 地址发过请求。

### 1. 数怎么拿

- 地址的写法：`https://geesonchan.goatcounter.com/counter/[PATH].json`。帮助页原话："The `[PATH]` is the full path, including a leading `/`"。帮助页里的例子用 `encodeURIComponent(path)` 编码。
- 返回什么：一个对象，里面的 `count` 是"total number of visitors as a formatted string with thousands separators"，也就是带千位分隔的字符串，比如 `"1,234"`。`count_unique` 是旧字段，新代码不要用。（帮助页）
- 另一个办法是 count.js 的 `visit_count()`：它往页面里插一个 iframe 或图片，默认还带 "by GoatCounter" 字样。D24 定了不用 count.js，所以打算用 `fetch` 取 JSON，自己显示。（帮助页；count.js 的做法见源码 `public/count.js` 第 203–236 行）
- 跨站读取：源码对 `.json` 加了 `Access-Control-Allow-Origin: *`（`handlers/vcounter.go` 第 289–291 行），所以 github.io 上的页面可以用 `fetch` 读。文档没写这一点。

### 2. 只算展厅自己的路径，不用 TOTAL

- 帮助页："The special path `TOTAL` … can be used to display the site totals"。TOTAL 是整个 GoatCounter 站的总数。
- 这个 GoatCounter 站和 game-of-life 共用，用 TOTAL 会把它也算进来。所以只取展厅自己的路径。

### 3. 路径到底是哪一个

- 页面现在送的是 `location.pathname`，线上就是 `/appliance-showcase/`（`src/analytics.ts`，`setupAnalytics`）。分享链接的问号后面那段从来不送（D24），所以从分享链接打开的页面也记在同一个路径下。
- 文档只说"包括开头的 `/`"。源码里：
  - 记录访问时，路径两头的 `/` 会被去掉再加回开头那个（`hit.go` 第 89 行），所以存下来的是 `/appliance-showcase`，没有结尾的斜杠；
  - 读数时先按原样找，找不到再同样去掉两头的斜杠找一次（`handlers/vcounter.go` 第 260–270 行），不分大小写。
- `/appliance-showcase/index.html` 会被当成另一个路径。这是从源码推的，源码里没有把它和 `/` 合并的地方；GitHub Pages 平时给的是 `/appliance-showcase/`。
- 做的时候：开关打开后，用你在后台看到的数核对页面取到的数，不靠推断。

### 4. 算的是什么

- 帮助页两处说法不一样：开头说 "a page's view count"，讲 JSON 时又说 "total number of visitors"。
- 源码算的是"访客"，不是"浏览次数"：
  - 只计每个会话在这个路径上的第一次访问（`cron/hit_count.go` 第 34–36 行）；
  - 一个会话 8 小时（`memstore.go` 第 296、342 行）。
  - 所以同一个人 8 小时里刷新十次，只算一次。
- 时间范围：默认从有记录起全部算（帮助页："default is to include everything"）。可以带 `start`，取值是 `week`、`month`、`year` 或某个日期；也可以带 `end`（帮助页；源码 `handlers/vcounter.go` 第 128–148 行）。

### 5. 哪些访问不算

文档没写，都是从源码和我们自己的代码看到的：

- 机器人不算：GoatCounter 自己判断出的机器人另存一张表，不进这个数（`memstore.go` 第 223–226 行）。我们送的时候也带了机器人标记（`src/analytics.ts` 的 `botScore`）。
- 后台「Ignore IPs」里的地址来的访问，根本不记录（`handlers/count.go` 第 44–49 行）。
- 在 `#toggle-goatcounter` 关掉计数的浏览器（店里自己的电脑）：我们的代码看到这个标记就不送（`src/analytics.ts` 的 `skipgc`），所以也不算。

### 6. 数会晚几个小时

- 帮助页原话："The responses are cached for up to four hours, so new pageviews don't show up right away."
- 源码：服务器端缓存 4 小时，刷新期间最多给 8 小时前的旧数；在地址后面加随机参数也绕不过去（`handlers/vcounter.go` 第 112、272–274、300–313 行）。

### 7. 开关没开、没有访问、取不到的时候

- 开关没开：帮助页只说要打开，没写会回什么。
  - 源码回 403，而且这时还没加跨站许可（`handlers/vcounter.go` 第 251–253 行）。
  - 所以页面上的 `fetch` 会直接失败，读不到内容。这是从源码推的。
- 路径还没有访问：帮助页例子的注释说 "Will return HTTP status 404 if the path is not found"。
- 页面的做法：失败、403、404、超时（打算 5 秒），一律当"取不到"处理：
  - 不报错；
  - 不挡别的东西，不等它；
  - 显示什么照你第 4 题的答复。

### 8. 打开开关的影响（你开之前请知道）

- 帮助页说这个开关默认关着，是 "to prevent unintentional leaking of data"。
- 开关是整个 GoatCounter 站的。打开以后，任何人都能读这个站里任何路径的数和 TOTAL，包括 game-of-life 的。源码里没有按路径单独许可的地方，这一条是从源码推的。

- **甲（底部提示行里，版本号前面）**：电脑上这一行压在木地板上，字本来就淡，加进去的访问次数也几乎看不清。

## 六、问题（等你答，没有替你选）

1. **显示在哪？**
   - 甲：底部提示行里；
   - 乙：顶栏标题右边；
   - 别的地方（请说）。
2. **句子怎么写？** GoatCounter 算的是访客（同一个人 8 小时内只算一次），不是打开次数。
   - 中文可以是「1,234 次访问」「已有 1,234 位访客」「访客 1,234」……
   - 英文可以是 "1,234 visits"「1,234 visitors」……
   - 请定中英文各一句。
3. **算哪些访问？**
   - 时间：从有记录起全部（默认）、最近 30 天（`start=month`），还是从某一天起；
   - 只算展厅自己的路径（我建议这样），还是用 TOTAL（会把 game-of-life 也算进来）。
4. **取不到时显示什么？**（开关没开、被拦、超时、出错）
   - 什么都不显示；
   - 显示一个占位，比如「—」；
   - 显示这台浏览器上次取到的数。
5. **手机上显不显示？**
   - 显示的话，放在原型的画面左上角，还是别处；
   - 不显示的话，就只有电脑上有。
6. **什么时候做？**
   - 先做好：开关没开时线上照第 4 题处理，你一开数就出来；
   - 还是等你开了开关再动手。
7. **数字的样子**：GoatCounter 给的是带千位分隔的字符串，分隔符跟后台的数字格式设置走。照原样显示，还是页面按语言自己排？
